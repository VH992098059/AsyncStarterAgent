1. 项目概述与背景

项目背景

拖延症的"冷启动"问题是知识工作者面临的核心效率障碍。心理学研究表明，拖延并非简单的懒惰，而是一种情绪调节失败——当面对复杂、模糊或令人焦虑的任务时，大脑的杏仁核会触发回避反应，导致行为上的延迟。Steel (2007) 的元分析研究指出，约 80%-95% 的大学生存在拖延行为，而成年职场人群中这一比例也高达 20%-25%。

传统任务管理工具（Todoist、滴答清单等）仅解决"记录"问题，却无法解决"启动"问题。用户将任务添加到清单后，面对空白文档或复杂的项目框架，仍然需要克服巨大的认知阻力才能开始。这种从"0到1"的阻力远大于从"1到1.1"的修改阻力——这正是本产品要解决的核心痛点。

Pychyl & Sirois (2016) 的研究进一步揭示，拖延的本质是"对负面情绪的短期优先回避"。当任务触发焦虑、无聊或自我怀疑时，人们倾向于选择即时满足的替代活动。因此，降低任务启动的认知门槛——通过自动化生成初始草稿，将用户从"创作者"角色转换为"审查者"角色——是从认知层面对抗拖延的有效策略。

解决方案

本产品采用"事件驱动的异步Agent"架构，核心工作原理如下：当系统检测到预设的触发条件（关键词匹配、DDL临近、Webhook事件推送、用户手动点击）时，自动启动一个后台AgentRun实例。该实例按照"触发 → 搜集 → 生成 → 交付"的四阶段流水线执行任务。

在上下文搜集阶段，Agent并行拉取用户的多维数据源（GitHub提交记录、日历会议、IM消息、笔记内容），经过双层噪音过滤（规则引擎 + LLM语义判断）后，构建结构化的上下文快照。在草稿生成阶段，Agent通过RAG语义检索召回最相关的素材，套用预设Markdown模板，再由LLM润色生成连贯的段落文本，并在需要用户主观判断的位置插入[待补充]标记。

最终，草稿通过交付管道自动写入用户指定的目标平台（Notion页面、Obsidian文件、飞书文档），并将文档链接回写到原始待办任务。整个过程中，用户只需在收到通知后审核和微调草稿，将认知负荷从"从零创作"降低到"审查修改"。

目标用户

独立开发者

日常需要撰写周报、项目总结、技术方案文档，但常常因为"不知道从何写起"而拖延到最后一刻。他们有丰富的代码提交记录和技术讨论，但缺乏将这些碎片信息组织成结构化文档的启动动力。本产品自动从GitHub提交和IM讨论中提取素材，生成30%-40%完成度的草稿骨架，让开发者只需补充关键决策和主观判断即可。

项目经理

每周需要汇总团队进展、撰写项目状态报告、准备会议纪要，但信息散落在飞书群聊、日历会议、Jira/Notion任务中，手动收集整理耗时且容易遗漏。本产品自动聚合多源数据，按"本周进展/风险阻塞/下周计划"等板块分类填充，项目经理只需审核关键信息并补充战略判断，将周报撰写时间从2小时压缩到20分钟。

知识工作者

日常需要撰写学习总结、读书笔记、会议记录、季度复盘等文档，但面对空白页面时容易产生写作焦虑。他们在Obsidian/Notion中积累了大量碎片笔记，却很少将它们整合为结构化的输出。本产品自动检索相关笔记素材，按文档类型套用模板生成初稿，并在需要个人见解的位置留下[待补充]标记，引导用户逐步完成文档。

核心理念

本产品的核心理念是实现用户从"创作者"到"审查者"的角色转变。传统工作流要求用户面对空白页面从零开始创作，这恰恰是拖延症的温床——空白页面引发的焦虑感会激活大脑的回避机制，导致任务被无限期推迟。

本产品通过Agent自动完成最困难的"从0到1"阶段：搜集素材、搭建框架、填充内容、标记待补充位置。用户收到的不再是空白页面，而是一份完成度30%-40%的结构化草稿，其中客观信息（代码提交、会议记录、讨论摘要）已经自动填充，仅剩主观判断（方向选择、优先级决策、个人见解）需要用户补充。

这种角色转变利用了认知心理学中的"锚定效应"——人们修改已有内容的心理阻力远低于从零创建。同时，[待补充]标记机制将模糊的"写完这篇文档"分解为具体的"回答这3个问题"，进一步降低了认知负荷，使任务启动变得自然而非对抗。

产品定位声明

"完成前30%" 异步行动起跑器 Agent 是一款面向知识工作者的智能任务启动工具，通过事件驱动的后台Agent自动搜集用户上下文数据并生成结构化草稿，将用户从"面对空白页面的创作者"转变为"审核微调的审查者"，从根本上解决拖延症的冷启动问题，让每一次任务都能轻松起跑。

2. 功能性需求清单

4个模块 / 20项需求 / 每项包含完整字段定义

FR-A01关键词触发P0

系统检测待办任务中包含预设关键词模式（正则匹配"写|准备|规划|整理|总结"等动词+名词组合），自动创建AgentRun实例。关键词模式支持用户自定义扩展，系统内置常见任务动词词库，匹配时综合考虑动词类型和名词上下文，避免对孤立动词的误触发。

输入Webhook事件体 / 轮询结果（含任务标题、描述、标签）输出AgentRun任务实例（含trigger_type=keyword, matched_pattern）验收标准关键词匹配准确率 > 95%，误触发率 < 5%，匹配延迟 < 500ms异常处理关键词冲突时取最长匹配；正则引擎超时（>1s）时降级为精确匹配依赖关系FR-A03（Webhook接入提供事件源）
FR-A02DDL触发P1

系统定时扫描（每15分钟）待办任务的截止日期，当距离DDL小于配置阈值时自动触发AgentRun。提前量默认24小时，用户可在设置中自定义（范围1h-72h）。同一任务不重复触发，通过triggered_ddl_tasks集合去重。

输入任务DDL + 配置的提前量阈值（默认24h）输出AgentRun任务实例（含trigger_type=ddl, task_deadline）验收标准提前量可配置（1h-72h），不重复触发同一任务，扫描周期15min异常处理DDL变更时重新计算触发时间；任务被删除时跳过；时区差异以用户配置为准依赖关系FR-A03（Webhook接入提供任务同步）
FR-A03Webhook接入P0

提供统一的Webhook接收端点，支持Todoist/飞书/Notion的事件推送。每个平台的Webhook包含签名验证（HMAC-SHA256）和幂等处理（基于event_id去重），确保事件不丢失且不重复处理。端点支持健康检查和重试确认机制。

输入HTTP POST请求体 + 签名头（X-Todoist-HMAC-SHA256 / X-Feishu-Signature等）输出解析后的标准化事件对象（含source, event_type, payload, event_id）验收标准3平台Webhook验签通过，重复事件不重复处理，响应时间 < 200ms异常处理签名验证失败返回403；请求超时重试3次（指数退避）；payload解析失败记录原始数据依赖关系无（基础模块）
FR-A04手动触发P1

用户在界面点击"帮我起跑"按钮，选择任务类型（周报/总结/规划/会议纪要）和数据源范围后手动启动Agent。界面提供任务类型选择器和数据源勾选面板，支持快速启动和高级配置两种模式。

输入用户点击事件 + 任务类型选择 + 数据源范围勾选输出AgentRun任务实例（含trigger_type=manual, user_selected_sources）验收标准点击后 < 1秒返回任务ID，支持并发限制（最多3个同时运行）异常处理并发超限返回429+排队提示；数据源未授权时提示配置；网络中断时本地缓存请求依赖关系FR-A03（Webhook接入提供事件标准化）
FR-B01GitHub数据拉取P0

通过GitHub REST API v3拉取用户本周的Commit记录（含message、文件变更统计、关联PR）、PR列表（含标题、状态、review评论、变更文件数）、Issue评论。支持增量同步，API限流时自动退避（检测X-RateLimit-Remaining头），Token过期时通知用户重新授权。

输入GitHub username + OAuth token + 时间范围（默认本周）输出结构化Commit/PR/Issue列表（含sha, message, stats, url）验收标准增量同步不重复拉取，API限流时自动退避，403时使用缓存数据异常处理Token过期通知重新授权；403 Forbidden使用缓存数据；网络超时重试3次依赖关系FR-B06（增量同步机制）
FR-B02日历数据拉取P1

通过Google Calendar API v3 / Microsoft Graph API拉取本周会议事件，包含主题、参会人列表、会议时长、会议笔记（如有）。双平台通过适配器模式统一接口，OAuth2.0授权流程完整实现（含refresh token自动刷新）。

输入OAuth2.0授权凭证 + 时间范围（默认本周）输出结构化会议列表（含title, attendees, duration, notes, time_range）验收标准支持Google/Outlook双平台，OAuth2.0授权流程完整，refresh token自动刷新异常处理授权失效时跳过该数据源并通知用户；API限流时使用缓存；日历为空时返回空列表依赖关系FR-B06（增量同步机制）
FR-B03IM消息拉取P1

通过飞书开放平台API / Slack Web API拉取用户本周发送的消息和标记为待办的讨论，按频道/群组分组。支持关键词过滤和时间段筛选，对同一讨论串中的消息进行去重和摘要合并，避免信息冗余。

输入API token + 时间范围 + 用户ID + 可选关键词过滤列表输出分组消息列表（含channel, messages[], thread_summary, is_todo）验收标准支持飞书/Slack双平台，关键词过滤和时间段筛选，去重处理异常处理API限流时使用缓存数据；Token失效跳过并通知；消息格式异常时记录原始数据依赖关系FR-B06（增量同步机制）
FR-B04笔记数据读取P1

Obsidian通过本地文件系统读取Vault目录下本周修改的.md文件（基于文件修改时间筛选）；Notion通过API读取指定数据库中本周新建/修改的页面。两种模式通过适配器统一接口，Obsidian本地读取无需API调用，Notion支持数据库查询和单页面读取两种模式。

输入Obsidian Vault路径 / Notion数据库ID + API token + 时间范围输出笔记内容列表（含title, tags, modified_at, content_preview）验收标准Obsidian本地读取无需API，Notion支持数据库和页面两种模式异常处理Vault路径不存在时提示配置；Notion API限流时排队重试；文件编码异常时跳过依赖关系FR-B06（增量同步机制）
FR-B05噪音过滤P0

使用规则引擎+LLM双层过滤机制。规则层（快速过滤）过滤请假/打卡/日常问候/系统通知等模式化内容；LLM层（语义过滤）判断剩余信息与当前任务的相关性，保留有价值的讨论、决策记录和待办事项。两层串联执行，规则层先过滤明显噪音，LLM层再精细筛选。

输入原始数据流（来自B01-B04）+ 任务上下文（任务类型、关键词）输出过滤后的有效数据（含relevance_score, filter_reason）验收标准过滤准确率 > 85%，误杀率 < 10%，处理延迟 < 3秒异常处理LLM调用失败时仅使用规则层过滤；规则引擎异常时放行所有数据并告警依赖关系FR-B01 ~ FR-B04（数据源提供原始数据）
FR-B06增量同步P0

基于每个数据源的last_sync_timestamp实现增量拉取。每次同步完成后更新时间戳为当前时间，下次拉取仅获取该时间戳之后的新增数据。支持手动重置时间戳以触发全量同步，时间戳以UTC格式存储以避免时区问题。

输入数据源配置 + last_sync_timestamp（UTC）输出增量数据集 + 更新后的last_sync_timestamp验收标准不重复拉取已同步数据，支持全量重置，时间戳精度到秒异常处理时间戳冲突时以服务端最新时间为准；同步中断时不更新时间戳依赖关系无（基础模块）
FR-C01RAG语义检索P0

将搜集的上下文数据进行Embedding后存入PostgreSQL向量数据库（pgvector扩展），根据任务描述进行语义检索召回最相关的Top-K素材。Embedding模型支持配置切换（默认text-embedding-3-small），检索时结合元数据过滤（时间范围、数据源类型）提升精度。

输入任务描述 + 上下文数据集 + Top-K参数（默认10）输出Top-K相关素材（含content, relevance_score, source_type, metadata）验收标准召回率 > 80%，检索延迟 < 5秒，支持元数据过滤异常处理向量库不可用时降级为关键词检索（TF-IDF）；Embedding失败时跳过该条数据依赖关系FR-B05（噪音过滤提供清洗后数据）
FR-C02模板套用P1

根据任务类型选择预设Markdown模板（周报/总结/规划/会议纪要），将RAG检索到的素材按模板板块分类填充。模板采用板块-槽位结构，每个板块定义标题、排序和素材匹配规则，素材通过LLM辅助分类到对应板块。

输入任务类型 + 模板库 + RAG检索结果（分类后的素材）输出填充后的模板骨架（Markdown格式，含板块标题+素材摘要）验收标准支持4种以上模板，板块分类准确率 > 90%，无匹配模板时使用通用模板异常处理无匹配模板时使用通用模板；素材无法分类时放入"其他"板块依赖关系FR-C01（RAG检索提供素材）
FR-C03LLM润色生成P0

使用LLM对模板骨架进行自然语言润色，生成连贯的段落文本。保持专业语气，控制输出在30%-40%完成度（即保留[待补充]空间）。生成参数支持temperature（默认0.3）和max_tokens配置，通过SSE流式输出实时推送给前端。

输入模板骨架 + RAG素材 + 生成参数（temperature, max_tokens）输出润色后的草稿文本（SSE流式输出，含completion_percentage）验收标准文本通顺度 > 4/5分，完成度30%-40%，首token < 2秒异常处理LLM超时重试2次（指数退避），仍失败返回模板骨架；内容安全过滤触发时替换敏感段落依赖关系FR-C02（模板骨架提供结构）
FR-C04[待补充]标记P1

LLM在生成过程中识别需要用户主观判断的位置（如"下周重点方向"、"遇到的挑战"、"关键决策点"），插入[待补充:提示文字]标记。标记在前端以高亮可点击形式展示，点击后定位到对应编辑位置。每个草稿至少包含2个标记，引导用户完成关键信息的补充。

输入草稿文本 + 标记规则（定义哪些类型的内容需要标记）输出含[待补充:提示文字]标记的草稿（标记含id, hint, position）验收标准标记位置准确，可点击定位，每个草稿至少2个标记异常处理无合适标记位置时不强制插入；标记解析异常时忽略该标记依赖关系FR-C03（LLM生成提供草稿文本）
FR-C05SSE流式输出P0

草稿生成过程通过Server-Sent Events实时推送给前端。SSE事件类型包括：stage_start（阶段开始）、chunk（文本片段）、stage_complete（阶段完成）、run_complete（运行完成）、error（错误）。支持客户端中断和断线重连，断线后从上次接收位置继续。

输入AgentRun ID + 客户端SSE连接输出SSE事件流（data: {type, content, position, timestamp}）验收标准首token延迟 < 2秒，支持断线重连，中断后可恢复异常处理连接断开时缓存已生成内容（保留30分钟）；重连时从断点续传；超时无心跳时关闭连接依赖关系FR-C03（LLM生成提供流式内容）
FR-D01Notion页面创建P0

通过Notion API在用户指定的工作区/数据库下创建新页面，支持富文本块（children blocks：paragraph, heading, bulleted_list, to_do等）和属性（properties：title, tags, date等）。Markdown草稿自动转换为Notion块格式，保留标题层级和列表结构。

输入草稿Markdown内容 + 目标页面ID/数据库ID + 属性映射配置输出创建的页面URL（含page_id）验收标准支持富文本和数据库页面，页面结构完整，格式转换正确异常处理API限流时排队重试（指数退避）；权限不足时提示授权；页面创建失败时缓存内容依赖关系FR-C04（含标记的草稿提供内容）
FR-D02Obsidian文件写入P1

在用户配置的Obsidian Vault路径下创建.md文件，支持自定义子目录和文件名模板（如: YYYY-MM-DD-任务名.md）。Markdown格式保持原始结构，[待补充]标记以Obsidian callout语法渲染，支持YAML frontmatter元数据。

输入草稿Markdown + Vault路径 + 文件名模板 + 子目录配置输出文件完整路径（绝对路径）验收标准文件路径可配置，Markdown格式正确，YAML frontmatter完整异常处理路径不存在时自动创建目录；文件名冲突时追加序号；写入权限不足时提示依赖关系FR-C04（含标记的草稿提供内容）
FR-D03飞书文档创建P2

通过飞书开放平台API v2在用户指定的飞书空间创建文档，支持富文本格式转换（Markdown转飞书文档块）。飞书文档的块模型与Notion不同，需要独立的格式转换器处理标题、列表、代码块等元素。

FR-D04任务备注更新P0

3. 非功能性需求

NFR-01性能

端到端延迟

完整AgentRun从触发到交付 < 30秒。分解指标：触发阶段 < 1秒（事件解析+任务识别），上下文搜集 < 15秒（并行拉取+噪音过滤），草稿生成 < 10秒（RAG检索+模板套用+LLM润色），交付 < 4秒（格式转换+平台写入+链接回写）。

关键性能指标

  • ▸SSE首token延迟 < 2秒
  • ▸API响应时间 < 500ms（P95）
  • ▸并发支持10个AgentRun同时运行
  • ▸RAG检索延迟 < 5秒
NFR-02安全

认证与授权

所有第三方数据源接入均使用OAuth2.0授权流程，支持refresh token自动刷新，Token过期前5分钟主动刷新。用户API Key使用AES-256-GCM加密存储，解密密钥通过系统环境变量注入，不落代码仓库。

传输与验签

  • ▸所有外部通信强制HTTPS (TLS 1.3)
  • ▸Webhook入站使用HMAC-SHA256签名验证
  • ▸敏感数据（Token/Key）不落日志，日志脱敏处理
  • ▸API接口实施Rate Limiting（按用户+IP双维度）
NFR-03可用性

服务可用性目标

99.5%服务可用性（月度），允许每月最多3.6小时不可用。提供/health和/readiness健康检查端点，支持Kubernetes探针。进程异常退出时自动重启（supervisor管理），重启时间 < 30秒。

容错与降级

  • ▸优雅降级：单数据源不可用时跳过继续
  • ▸自动重试：3次指数退避（1s, 2s, 4s）
  • ▸断路器模式：连续5次失败后熔断，30秒后半开探测
  • ▸数据源状态面板：实时展示各数据源连接状态
NFR-04可扩展性

插件化架构

数据源适配器采用插件化设计，实现DataSource接口（Fetch/Parse/Filter三个方法）即可接入新数据源，无需修改核心代码。适配器通过配置文件注册，支持热加载。LLM Provider同样可切换（OpenAI/Claude/国产大模型），通过LLMProvider接口抽象。

水平扩展

  • ▸服务无状态设计，支持水平扩展（Session外置到Redis）
  • ▸模板支持热加载（文件系统watcher监听变更）
  • ▸AgentRun任务队列支持分布式消费（基于Redis Stream）
  • ▸向量数据库支持分片和副本，随数据量线性扩展
NFR-05数据隐私

数据存储策略

用户数据本地优先存储（SQLite/本地文件系统），仅在用户明确授权时同步到云端。向量数据使用AES-256加密存储，Embedding过程在本地完成（支持本地模型）。数据保留策略默认90天，超期自动清理，用户可自定义保留期限。

隐私保障

  • ▸用户可随时删除全部数据（一键清除+确认）
  • ▸不使用用户数据训练或微调任何模型
  • ▸LLM调用时对敏感信息（邮箱/手机号/身份证）脱敏
  • ▸数据导出功能：支持JSON/Markdown格式导出用户全部数据

4. 技术选型决策记录

Go + Gin后端框架

Go语言提供高性能HTTP服务，Gin框架轻量且中间件生态丰富。goroutine天然适合异步并发场景——每个AgentRun作为一个goroutine独立运行，上下文搜集阶段的多个数据源并行拉取通过goroutine+channel实现，无需线程池管理。编译型语言部署简单（单一二进制文件），交叉编译支持多平台。Gin的中间件机制便于实现认证、限流、日志等横切关注点。

EinoAgent编排

字节内部Agent编排框架，提供DAG式流程控制能力。AgentRun的四阶段流水线（触发→搜集→生成→交付）通过DAG定义节点和边，支持条件分支和并行执行。内置重试和错误处理机制，节点失败时可根据配置选择重试、跳过或终止。原生支持流式输出（SSE），与前端实时交互无缝衔接。框架还提供可观测性支持（trace/metrics/log），便于调试和监控。

PostgreSQL + pgvector向量数据库

使用PostgreSQL的pgvector扩展实现向量存储与检索，无需额外部署独立的向量数据库服务。pgvector支持IVFFlat和HNSW索引，万级到十万级向量场景下性能完全满足MVP需求。与业务数据同库管理，减少运维复杂度，事务一致性有保障。后续如需亿级规模可迁移至Milvus，但MVP阶段pgvector是最务实的选择——少一个组件就少一个故障点。

Tauri v2方案一：桌面端

Rust安全内核+Web前端生态，安装包极小（10-20MB vs Electron 100MB+）。v2版本支持iOS/Android移动端，通过Swift/Kotlin桥接调用原生API。Rust层负责文件系统访问（Obsidian Vault读取）、安全存储（Token加密）和系统托盘，Web层负责UI渲染和交互。IPC通信机制安全高效，支持双向事件流。

Flutter方案二：跨端

Impeller GPU渲染引擎提供流畅的原生体验，60fps动画无卡顿。插件生态丰富（sqflite本地存储、flutter_secure_storage安全存储、url_launcher系统交互），跨端视觉一致性优于React Native。Dart语言的Isolate模型天然适合并发任务处理，与后端AgentRun的异步模型契合。支持桌面端和移动端。

Axios / DioHTTP客户端

Axios（Tauri方案）：请求拦截器统一注入认证头，响应拦截器处理错误码和Token刷新，支持请求取消和重试，TypeScript类型定义完整。Dio（Flutter方案）：拦截器机制与Axios类似，额外支持FormData上传、缓存策略和请求取消，与Flutter生态深度集成。两者均支持SSE流式响应处理。

5. 数据流设计

四阶段流水线：Ingestion → Context Harvesting → Synthesis → Delivery

STAGE 1

Ingestion

输入

Webhook事件体、关键词匹配结果、DDL到期扫描结果、用户手动触发请求

处理

事件解析 → 签名验证（HMAC-SHA256） → 幂等去重（event_id） → 任务识别 → 触发判定 → 创建AgentRun

输出

AgentRun任务实例（run_id, trigger_type, task_type, status=pending）

异常

签名失败→403；重复事件丢弃；并发超限→429；解析失败记录原始数据

STAGE 2

Context Harvesting

输入

AgentRun实例 + 用户数据源配置 + last_sync_timestamp

处理

并行拉取（goroutine并发） → 增量合并（时间戳去重） → 双层噪音过滤（规则+LLM） → 结构化输出

输出

结构化上下文快照（commits[], meetings[], messages[], notes[]）

异常

单数据源失败跳过继续；API限流自动退避；Token过期通知；LLM过滤失败降级

STAGE 3

Synthesis

输入

上下文快照 + 任务类型 + RAG检索结果 + 模板库

处理

Embedding+向量检索 → 模板选择+素材分类 → LLM润色生成（SSE流式） → [待补充]标记插入

输出

结构化草稿（Markdown，完成度30%-40%，含[待补充]标记）

异常

向量库不可用降级关键词检索；LLM超时重试后返回模板骨架；SSE断线缓存30分钟

STAGE 4

Delivery

输入

审核后的草稿 + 交付目标配置（Notion/Obsidian/飞书） + 原始任务信息

处理

格式转换（Markdown→目标平台块格式） → 平台写入 → 链接回写 → 通知推送

输出

交付确认（delivery_id, target_url） + 任务备注更新 + 应用内通知

异常

API限流排队重试；权限不足提示授权；任务已删除记录日志；通知失败静默处理

9. 风险与缓解措施

高API限流

风险描述：第三方API调用频率超限导致数据拉取失败，影响上下文搜集阶段的完整性，进而降低草稿质量。

缓解措施：请求限流（令牌桶算法）+ 指数退避重试（1s/2s/4s）+ 缓存兜底（使用最近一次成功拉取的数据）+ 降级策略（单数据源失败时跳过继续）。

高授权失效

风险描述：OAuth Token过期或被用户撤销，导致数据源连接中断，无法拉取最新数据。

缓解措施：自动refresh token（过期前5分钟主动刷新）+ 失效通知（推送应用内通知引导重新授权）+ 重新授权引导（一键跳转授权页面）+ 缓存兜底。

中LLM质量

风险描述：LLM生成内容偶发偏离预期，出现事实错误、语气不当或结构混乱，影响草稿可用性。

缓解措施：多轮润色（初稿→审查→修正循环）+ 温度控制（默认0.3降低随机性）+ 人工反馈闭环（用户标记不满意段落，优化Prompt）+ Prompt版本管理。

中数据隐私

风险描述：用户数据跨境传输和存储的合规风险，特别是涉及个人通信和代码内容的处理。

缓解措施：本地优先存储 + 敏感脱敏（LLM调用前脱敏邮箱/手机号等）+ 数据保留策略（默认90天自动清理）+ 不训练模型。

中系统可用性

风险描述：单点故障导致服务不可用，如数据库宕机、LLM API大面积故障、网络分区等。

缓解措施：健康检查（/health + /readiness端点）+ 自动重启（supervisor管理）+ 优雅降级（单数据源不可用时跳过继续）+ 断路器模式。

低依赖升级

风险描述：第三方API版本升级导致接口不兼容，如字段变更、认证方式更新、废弃端点等。

缓解措施：适配器模式隔离（每个数据源独立适配器）+ 版本锁定（依赖版本pin到具体版本号）+ 变更监控（订阅第三方API changelog）。
